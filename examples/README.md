# 表示の設定例

`dashboard.yaml` のentity_idを自分のセンサーへ変更してください。

`scripts.json` に開始・終了・表示テストの3スクリプトを収録しています。
`notify.mobile_app_YOUR_DEVICE` とセンサー、ダッシュボードURLを変更し、HAのスクリプト設定へ登録してください。

- 開始は発車予定の2時間前から。カウントダウンの対象時刻は開始時に固定します。
- 接近位置・混雑の変更を最大2分に1回送信します。APIの30秒取得とは別です。
- 発車予定から2分、または開始から30分で終了します。「終了」でも止められます。
- 「表示テスト」は実際の便と無関係な2分のタイマーです。

iOS 17.2以降・HA Core 2026.7以降と、CompanionアプリからHAへの接続が必要です。
iOSのタイマー表示では本文が置き換わります。端末の表示・通知設定により見え方や更新遅延が変わります。

## 平日朝の連続表示

`morning-automations.json` を自分の通知先に置換して登録すると、月〜金の8時に開始し10時に終了します（HAのタイムゾーン基準、祝日も含む）。HA再起動時も時間帯内なら再開します。「終了」で当日分を止められます。

朝用スクリプトは次の発車予定へ切り替わります。カウントダウンは端末側、バー・接近情報は最大約2分ごとの通知更新です。バーは前便〜次便の予定間隔に対する残り時間を表し、バスの走行進捗ではありません。通知の遅延で表示が遅れる場合があります。

`Stops remaining` は次の停留所から乗車停留所まで、乗車停留所を含む数です。次が乗車停留所なら1。循環路線で未通過の同名乗車地点が複数ある場合や停留所順が欠ける場合は推測せず不明になります。取得できない時は次の停留所名へ戻します。
